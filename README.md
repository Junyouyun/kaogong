# Kaogong 公考智能刷题应用

## 1. 项目定位

一个面向公务员考试的学习型大模型应用，覆盖行测与申论，目标不是做一个通用聊天机器人，而是完成“可信解题、申论诊断、错因分析、能力画像、个性化训练”的产品闭环。

产品的核心价值：

1. 行测答案和解析可验证，不依赖模型心算。
2. 申论评分有评分维度、材料证据和不确定性，避免只给一个无法解释的总分。
3. 每次练习都会更新知识点掌握度和错因画像。
4. 效果可以被稳定评测，而不是只凭主观感觉判断模型有没有变好。

## 2. 产品范围

### 2.1 行测

- 支持文本、图片、表格和整卷题目的导入。
- 支持 OCR、多模态识图和题目内容结构化。
- 覆盖言语理解、判断推理、数量关系、资料分析和常识判断。
- 提供三级辅助：方法提示、下一步提示、完整解析。
- 根据题目复杂度决定是否检索、检索什么以及是否进行多轮检索。
- 数量关系、资料分析等计算题调用 Python 或受控工具，不使用模型心算。
- 生成答案后执行校验：选项合法、计算结果一致、证据充分、答案与解析一致。
- 提供同知识点题、变式题和易错项分析。
- 支持计时练习、整卷模考、自动收卷和复盘。

### 2.2 申论

- 支持上传材料和题目，识别身份、任务、字数、格式和评分要求。
- 识别归纳概括、综合分析、提出对策、贯彻执行、文章写作等题型。
- 生成审题表和提纲，不默认替用户生成完整答案。
- 在材料中定位可引用的证据片段。
- 提供在线草稿编辑，并按要点覆盖、材料依据、逻辑结构、语言表达、格式规范分项评分。
- 指出空泛、脱离材料、要点重复、论据不足等具体问题。
- 保存不同修改版本，对比采分点覆盖和表达能力的变化。
- 分数必须附带证据、评分理由和不确定性；低置信度结果进入人工复核。

### 2.3 个性化学习闭环

- 记录正确率、耗时、错因和提示使用次数。
- 错因至少覆盖：知识缺失、理解错误、计算错误、粗心、时间不足、方法不当。
- 建立“知识点—前置知识—题型—错因”依赖图。
- 使用简化的能力值或 Elo 更新知识点掌握度；暂不引入复杂 IRT。
- 根据掌握度、考试频率、遗忘程度和剩余备考时间推荐练习。
- 生成每日训练计划、阶段报告和考前冲刺重点。

### 2.4 管理端与数据

- 题库批量导入、OCR 结果修正、重复题检测。
- 人工维护标准答案、解析、知识点和难度。
- 标注题目来源和授权状态，不抓取或分发未经授权的付费题库。
- 管理低置信度答案、用户反馈和申论人工评分样本。
- 管理提示词版本、模型版本、评测集和微调数据。

## 3. 核心工作流

### 3.1 行测

```text
题目文本/图片
  -> 内容解析与题型识别
  -> 判断是否需要检索
  -> 知识点、方法、相似题召回
  -> 必要的计算/规则工具
  -> 生成答案与分层解析
  -> 答案和证据校验
  -> 更新错因与知识点掌握度
  -> 推荐下一题
```

### 3.2 申论

```text
材料与题目
  -> 拆解任务和评分要求
  -> 生成审题表与提纲
  -> 用户写作/模型辅助修改
  -> 材料证据定位
  -> 分项评分与问题诊断
  -> 修改建议和版本对比
  -> 更新作答能力画像
```

## 4. 重点技术

| 技术 | 在本项目中的用法 |
| --- | --- |
| Adaptive RAG | 先判断是否需要检索，简单题直接回答，复杂题进入多轮检索 |
| 查询规划 | 将复杂题拆成知识点识别、方法检索、例题检索和答案校验 |
| Hybrid Retrieval | 向量检索、关键词/BM25、题型/年份/难度等元数据过滤 |
| Rerank | 对知识点、例题、方法和解析重新排序，控制上下文预算 |
| Program-aided Reasoning | 数量关系、资料分析和表格处理交给确定性代码 |
| Verifier | 检查答案、选项、计算过程、证据充分性和解析一致性 |
| Skill Graph | 建立知识点、前置知识和错因之间的关系，而不是为简历强上 GraphRAG |
| Stateful Workflow | 使用 LangGraph 管理提示、重试、中断恢复、长任务和人工审核 |
| Layered Memory | 分开保存会话记忆、错题记忆和能力画像 |
| Human-in-the-loop | 低置信度题目、争议答案和申论评分进入人工复核 |
| Structured Output | 使用 Pydantic/JSON Schema，保证结果可校验、可存储、可评测 |
| Model Routing | 简单任务使用小模型，复杂解题和申论使用更强模型 |
| Observability | 记录检索、Prompt、工具调用、模型版本、Token、耗时和失败原因 |
| LLM-as-Judge | 辅助申论评分，但必须用人工样本进行校准 |
| LoRA/DPO | 优化解析风格、结构化输出和申论偏好，不用来存储考试事实知识 |

## 5. 技术架构

```text
Next.js Web
    |
FastAPI API / Auth / Quota
    |
LangGraph 工作流编排
    |
┌──────────────┬──────────────┬──────────────┐
│ 题库与文档服务 │ 解题与工具服务 │ 学习画像服务 │
└──────────────┴──────────────┴──────────────┘
    |
PostgreSQL + pgvector + Redis
    |
模型网关 / Reranker / Python Sandbox
    |
Langfuse 追踪 + DeepEval/RAGAS 回归评测
```

建议技术栈：

- 前端：Next.js。
- 后端：FastAPI。
- Agent 工作流：[LangGraph](https://github.com/langchain-ai/langgraph)。
- 数据库：PostgreSQL + pgvector。
- 缓存与异步任务：Redis。
- 文件存储：本地对象存储，后续可迁移到 MinIO/S3。
- 可观测性：[Langfuse](https://github.com/langfuse/langfuse)。
- 评测：自定义业务指标、DeepEval，RAG 指标参考 RAGAS。
- 部署：Docker Compose。
- 微调实验：[LLaMA-Factory](https://github.com/hiyouga/LlamaFactory)。
- 后训练原理学习：[LLMs-from-scratch](https://github.com/rasbt/LLMs-from-scratch)、[smol-course](https://github.com/huggingface/smol-course)。

## 6. 微调与后训练路线

事实知识放在检索库，模型负责理解、推理、生成和格式化，避免用微调记题库。

1. 先建立稳定的应用评测集和失败样本收集机制。
2. 使用 LLaMA-Factory 跑 QLoRA 基线，形成可重复的训练配置。
3. 学习 LLMs-from-scratch 的训练循环、LoRA 和指令微调实现。
4. 通过 smol-course 完成 SFT、评测、DPO 和小规模强化学习实验。
5. 只有在应用失败样本足够多、数据质量可保证时，才制作自己的训练集。
6. 对比基础模型、RAG、RAG + LoRA、RAG + DPO，微调版本必须通过离线评测后才能进入生产。

候选微调任务：

- 行测解析的结构化输出和题型适配。
- 申论审题、分项评分和修改建议风格。
- 模型经常出现但检索无法解决的固定推理模式。

不把以下内容作为微调目标：

- 记忆考试题目和标准答案。
- 弥补检索库缺失的事实知识。
- 用 DPO 代替明确的业务规则和评分标准。

## 7. V1 上线验收标准

V1 是一次完整上线，不把核心业务拆成可对外发布的半成品版本。开发过程可以分模块实施，但只有以下条件全部通过才视为 V1 完成。

- 行测完整流程可用：练习、提示、解题、校验、错题、推荐和模考。
- 申论完整流程可用：审题、提纲、写作、评分、证据定位和修改对比。
- 所有 AI 输出结构化入库，并记录模型版本和 Prompt 版本。
- 所有低置信度内容可以拦截、重试或标记人工复核。
- 每次请求可以追踪完整的检索和工具调用过程。
- 在自有评测集上，行测答案准确率、解析一致率和申论评分校准达到设定门槛。
- 图片题、表格题、无答案题、错误 OCR 和模型超时等情况具有明确降级方案。
- 题目和材料记录来源与授权状态。
- 代码具备数据库迁移、单元测试、集成测试和 Docker 部署脚本。
- 微调数据导出和离线对照评测可用；微调模型超过基线后才允许进入生产。

## 8. 关键产品决策

1. 首版尽可能完整，不按“先随意做一个 MVP”缩减核心需求。
2. 后续依据真实产品反馈制作 V2，不依据开发过程中的临时想法随意改变 V1。
3. 新想法先进入待评估清单，不直接插队当前实现。
4. 核心业务使用代码优先的工作流，不把业务锁死在 Dify、RAGFlow 等平台中。
5. 采用固定但可分支的 LangGraph 工作流，不为了“先进”强行使用多智能体。
6. 使用知识点技能图解决学习诊断问题，不为简历强行加入 GraphRAG。
7. 申论评分允许模型辅助，但必须保留证据、评分理由、版本记录和人工校准机制。
8. 不抓取或分发未经授权的题库内容。

## 9. 明确不纳入 V1 的功能

- 直播课、社区、社交和付费体系。
- 未经授权的外部题库抓取与内容分发。
- 完全自动代替用户完成申论文章。
- 无沙箱、无权限限制的自主工具执行。
- 以多智能体自由对话作为核心解题方式。
- 为展示技术而引入 GraphRAG、复杂 IRT、Kubernetes 等非必要组件。

## 10. 实施顺序

以下顺序只表示开发依赖，不表示对外发布多个版本：

1. 产品模型、数据库设计、评测集和项目骨架。
2. 题库导入、OCR、解析、检索和题目管理。
3. 行测工作流、工具解题、答案校验和练习体验。
4. 申论工作流、证据定位、分项评分和版本管理。
5. 学习画像、错因分析、推荐和模考。
6. 可观测性、评测平台、权限、部署和运营后台。
7. 微调实验、离线对比和模型上线门禁。

全部模块完成并通过 V1 验收标准后，向真实用户开放并收集反馈。

## 11. 本地题库与运行

当前已完成本地题库规范化和可直接运行的刷题基础应用。

```powershell
# 首次安装后端依赖
python -m pip install -e .

# 从 data/external 下的原始题库生成本地规范化题库
python scripts\build_question_bank.py

# 启动本地应用
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

浏览器访问 `http://127.0.0.1:8000`。

当前规范化结果：

- `data/processed/question_bank.db`
- 公务员行测 27,506 道，506 套试卷。
- 公务员申论 3,458 道，909 套试卷。
- 申论材料 5,382 条，909 套试卷全部关联材料。
- 题目—试卷来源关系、选项、图片、答案复核记录和分析字段均已拆分入库。
- 行测支持随机练习、即时判分和解析；申论支持材料阅读和作答记录。

外部题库和生成题库均通过 `.gitignore` 排除，只用于本地测试。题库数据和下载来源记录在 `data/external/source-manifest.json`，不得直接用于公开分发、商业运营或模型训练。

## 12. AutoDL 远程环境

项目已部署到 AutoDL 摩尔线程实例：

- 项目目录：`/root/autodl-tmp/kaogong`
- GPU：MTT S4000，约 48 GB 显存
- 推理后端：`torch_musa`
- Web 服务监听：`0.0.0.0:6006`
- 公网地址：读取实例环境变量 `AutoDLService6006URL`

连接使用项目内独立密钥和配置：

```powershell
ssh -F D:\agent开发\kaogong\.ssh\config autodl-kaogong
```

同步代码并重启远端服务：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\sync_autodl.ps1
```

题库发生变化时同步规范化数据库：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\sync_autodl.ps1 -SyncData
```

项目内 `.ssh` 目录已加入 `.gitignore`，不得提交或分享私钥。

## 13. 登录、整卷与错题本

- 首次打开应用时必须创建管理员账号。
- 首次创建账号需要在页面填写本地 `.secrets/setup_token` 中的部署码。
- 管理员创建完成后，默认关闭公开注册。
- 只允许管理员在“用户管理”中生成一次性邀请码。
- 受邀用户通过“使用邀请码创建账号”完成注册，邀请码使用一次后失效。
- 管理员可以查看用户、答题数量、错题数量和最近活跃时间。
- 普通用户不能访问用户管理和邀请码接口。
- 登录使用 HttpOnly 会话 Cookie，密码使用 PBKDF2-HMAC-SHA256 加盐存储。
- 登录失败次数会按用户名和来源地址进行短时限制。
- 每名用户的答题记录、练习会话和错题本相互隔离。

整卷练习支持逐题练习和限时模拟考试：

- 答案暂存与恢复。
- 上一题、下一题和答题进度。
- 交卷后显示已答数量、判分数量和正确率。
- 交卷后可逐题查看参考答案与解析。

错题本自动收集客观题错误，记录错误次数，支持重做和手动移出。

### 邀请新用户

1. 管理员登录。
2. 进入“用户管理”。
3. 选择有效期并生成一次性邀请码。
4. 把邀请码发给受邀用户。
5. 受邀用户在登录页点击“使用邀请码创建账号”。
6. 注册成功后邀请码立即失效。
